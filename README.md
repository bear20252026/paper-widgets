# Paper Widgets

**Live shelf:** https://bear20252026.github.io/paper-widgets/

A library of finished, self-contained pieces — data desks and finance tables, small tools and sign-ins, product and
editorial pages, 3D objects and spatial interactions, scenes and animations, games and toys — plus a separate
Workshop for the cuts, studies and prototypes that are not finished editions. Pieces share a habit, not a codebase:
no shared package, no monorepo, no build tooling tying them together. A piece is a folder, its README, and the code
it needs.

**Seventy-eight finished pieces on the shelf; twenty-three in the Workshop. Six categories: Data, Widget, Page, Object, Scene, Play.**

## The library page

`gallery/index.html` is the finished shelf: 78 cards, searchable by text and filterable by category. The separate
`gallery/workshop/index.html` holds the 24 workshop pieces, also grouped by the same six categories; every card
carries a status badge and a note saying why it is there. Both pages are generated from `gallery/catalog.json`, and
the catalogue in this README is generated from the same file.

```bash
npm run install:pieces                    # once: npm ci (or install) in every Vite piece
npm run test                              # node --test: Puzzle Card's geometry, links, card format and server
npm run galleries                         # regenerate the shelf and workshop HTML from the catalog
npm run readme                            # regenerate the list in this README from the catalog
npm run site                              # build every Vite piece into site/, copy the static ones,
                                          # then regenerate the two gallery pages
npm run serve                             # http://localhost:4180
```

`npm run site` builds each Vite piece with `--base=./` and copies it to `site/<piece>/`; a static piece is copied as
it is, minus its README and the files a project keeps for itself (package.json, lint config, server, tests). The two
gallery pages, `gallery.css` and `gallery.js` are copied to `site/` on top. The whole library is a plain static folder —
drop it on GitHub Pages, Netlify or any static host.

`.github/workflows/pages.yml` does exactly that on every push to `main`: install each piece, build the shelf, publish
`site/` to GitHub Pages. No build secrets, no configuration — the workflow is the deployment.

## Working on one piece

```bash
npm run dev -- night-dial       # Vite pieces start their own dev server
npm run dev -- cathedral-walk   # static pieces are served from the shelf root
npm run dev --                  # list every piece
```

The original pieces keep shortcut scripts: `dev:widgets`, `dev:aquarium`, `dev:pip`, `dev:finance`, plus
`dev:sundrel`, `dev:lumiloom`, `dev:grow`, `dev:minionslab` and `dev:prism` for the static rooms. Puzzle Card has its own project
shell and server, so `dev:puzzle` runs that instead of a plain static server; `npm run test` runs its node tests.

Each Vite piece keeps its own `package.json`, lockfile, config and README. Static pieces need neither install nor
build: any static server will do, and `npm run dev -- <piece>` is one. Puzzle Card is the exception with a server:
`npm run dev:puzzle` serves its files and `/api/card`, so a short link works there instead of falling back to a long one.

## Layout

```
gallery/catalog.json          the table of contents, and the shelf / workshop decision for every piece
gallery/gallery.css           shared gallery style
gallery/gallery.js            search and category filters
gallery/index.html            generated shelf page (copied to site/index.html)
gallery/workshop/index.html   generated workshop page (copied to site/workshop/index.html)
scripts/build-galleries.mjs   generates both gallery pages from the catalog
scripts/build-readme.mjs      regenerates the catalogue block in this README
scripts/pieces.mjs            which pieces build, which are copied
scripts/install-pieces.mjs    installs every Vite piece
scripts/build-site.mjs        builds every piece into site/, then copies both galleries
scripts/dev-piece.mjs         runs one piece by name
scripts/serve-site.mjs        serves site/
scripts/serve-piece.mjs       serves one static piece straight from its folder
scripts/serve-static.mjs      the no-dependency server the last two use
CURATION.md                   the shelf / workshop criteria
paper-widgets/ … paper-snake/ one folder per piece
```

## Adding a piece

1. Add a folder with its own README — a Vite + React app, or a plain static app if it needs no build.
2. Add the folder name to `pieces` (built) or `staticPieces` (copied as is) in `scripts/pieces.mjs`.
3. Add a record to `gallery/catalog.json`: `category` is `data`, `widget`, `page`, `object`, `scene` or `play`; `tier` is `shelf` for the finished primary edition, `workshop` for an early
   cut, source cut, prototype, server-dependent shelf cut, alternate edition or study; add a short `kind` and `note`
   for workshop pieces.
4. Run `npm run galleries` and `npm run readme`; both pages and the list above update from the catalog.

## Notes

- No shared package, no monorepo tooling: a piece is a folder you can copy out.
- Every piece keeps its own palette. The paper rooms and ultramarine are a house style, not a rule; the scenes and
  dashboards bring their own colour.
- Some static scenes load three.js from a CDN, so they need a network connection. Vite pieces bundle what they use.
- The shelf holds the finished primary editions. First passes, source cuts, prototypes, server-dependent shelf cuts,
  alternate editions and single-technique studies are in the Workshop, separately. The split is recorded in
  `gallery/catalog.json` and explained in `CURATION.md`.
  Unless a piece says otherwise, no licence is granted beyond reading and learning.
- The Codevember works — three complete sets and thirteen single-prompt studies — were physically moved to
  [Nodevember's Codevember archive](https://github.com/bear20252026/nodevember/tree/main/codevember) on 2026-11-24.
  Their credits, source and licences travel with each folder; Paper no longer holds Codevember.
- Three of those travel light, and each piece's README says what was left out: Vinyl keeps the pressed records but not the
  source audio they were cut from, Splat Fashion keeps the 1M and 500k outfit packs but not the 2.9M one or the promotional
  clips, and Slop New York keeps the city and its data but not the authoring tools. Nothing a page loads at run time is
  missing.
- Some works arrived in several cuts. The finished primary edition is on the shelf; the other cuts are in the
  Workshop beside it, so they stay comparable without being mixed into the shelf. Copies with the same page code are
  one piece, even when line endings or a favicon-only line differ. Cuts that change the experience are separate pieces
  and say so in their title — the voxel and stylized koi, the modeled and image-based Aetheria, the two rain poems,
  the dormitory room and the dormitory RPG, the two Sable archive walls and the two Golden Hour Fox camera cuts.
